Note for Stakeholder Update — Victim Age Anomalies

During the data quality validation phase, several anomalous values were identified in the Vict Age variable.
The following situations were observed:
Some records contain negative age values (for example −1, −2, −3, −4), which are not logically valid and likely represent data entry errors.
A significant number of records report Vict Age = 0, which may indicate unknown or unreported age, rather than a real value.
A very small number of records show extreme age values (for example 120), which may represent outliers or potential data entry issues.
At this stage, these values have not yet been modified or removed from the dataset.
These anomalies will be presented to the stakeholder during the first project update meeting in order to confirm how they should be handled in the analysis (for example: treating them as missing values, excluding them from age-based analysis, or applying another rule).
Additional Data Quality Note — Victim Sex Categories
During the categorical validation of the Vict Sex variable, two uncommon values were identified.
The category X appears in cases where the victim’s sex is unknown or not reported. This frequently occurs in property crimes where the victim may be a business, organization, or property rather than an identifiable individual.
A very small number of records contain the value H, whose meaning is not clearly documented in the dataset and appears across different crime categories without a clear pattern.
Additionally, one record contains the value "-", which appears to be a data entry anomaly.
These observations will also be presented to stakeholders to confirm how these values should be treated in demographic analyses.

Analysis Step: Geographic Data Validation

During the geographic validation phase of the dataset, an additional consistency check was performed on the LOCATION, LAT, and LON variables.
The objective of this step was to verify whether each LOCATION value corresponded to a single geographic point or whether multiple coordinate pairs were associated with the same location.
To perform this check, the dataset was grouped by LOCATION and the number of distinct latitude and longitude values associated with each LOCATION was calculated.
The results showed that the majority of LOCATION values correspond to one or two coordinate pairs, indicating relatively stable spatial encoding in most cases. However, a limited number of locations are associated with a large number of coordinate pairs. These cases typically correspond to long streets or major urban corridors that span multiple geographic points across the city.
Examples of locations with high spatial variability include major streets such as Figueroa Street, Vermont Avenue, Broadway, and Western Avenue, which appear with hundreds of different coordinate pairs in the dataset. This behavior is expected because the LOCATION field represents street names or street segments rather than precise addresses.
To better understand the overall distribution of coordinate variability, descriptive statistics were computed for the number of distinct coordinates per LOCATION. The results show that the median number of coordinate pairs per location is 1, and 75 percent of locations are associated with two or fewer coordinate pairs. Only a small subset of locations shows a high number of distinct coordinates.
These results indicate that the LOCATION field is generally stable and usable for spatial reference, while a limited number of major streets naturally present higher coordinate variability due to their geographic extent.

Handling Missing Geographic Coordinates
During the same validation step, it was observed that some records contained LAT = 0 and LON = 0, which represent missing or invalid geographic coordinates.
To address this issue, the following recovery approach was implemented:
Records with valid coordinates were grouped by LOCATION.
For each LOCATION, the most frequent latitude–longitude pair observed in the dataset was identified.
Records containing zero coordinates were then matched with other records sharing the same LOCATION.
The most frequent coordinate pair for that location was used to replace the missing coordinates.
After applying this correction, an additional validation check was performed to identify any remaining records containing zero coordinates.
This approach ensures that missing spatial information is recovered using real coordinates observed in the dataset, rather than introducing arbitrary or externally generated geographic values.
