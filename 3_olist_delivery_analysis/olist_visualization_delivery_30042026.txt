VISUAL DESIGN AND VALIDATION RULES

Purpose:
Ensure that each visual is clear, readable, decision-oriented, and aligned with the validated KPIs.

Design rules:
- use insight-based titles, not generic metric names;
- keep labels short and understandable;
- show units clearly, for example %, days, or n;
- avoid overcrowded visuals;
- avoid redundant visuals;
- use consistent formatting across pages;
- highlight key values only when they support the message;
- ensure each page is understandable in 5 seconds.

Validation rules:
- each visual must answer one clear business question;
- each visual must support one validated insight;
- all aggregations must match the SQL output logic;
- percentages must be clearly labelled;
- order counts must be visible when volume matters;
- no misleading scales;
- no unnecessary technical fields visible to the stakeholder;
- geographic visual must be labelled as approximate ZIP-prefix mapping.

Power BI formatting decisions:
- use horizontal bar charts for comparison visuals;
- use data labels where values must be visible in PDF;
- use tooltips only as secondary support, not as required information;
- use map visual only for approximate geographic distribution;
- avoid raw SQL field names in titles and subtitles;
- prefer business-readable labels.

Accessibility / audience decision:
The presentation must remain operational-first and management-readable.
It should avoid SQL explanations and focus on what the data shows, why it matters, and what should happen next.

Geographic map limitation:
The map must explicitly state that coordinates are approximate ZIP-prefix coordinates derived from the OLIST geolocation table.
They do not represent exact seller, store, warehouse, hub, or marketplace partner locations.
