DATA INTAKE

ITA
Si presenta la necessità di importare più file CSV in PostgreSQL in modo efficiente e senza operazioni manuali ripetitive. L’approccio iniziale con pandas e to_sql consente automazione completa, ma risulta inefficiente per via dell’uso di operazioni INSERT multiple invece di un caricamento massivo che su un totale di 700mb di dati impiega 15 minuti per completare l'operazione.
Per migliorare le prestazioni si adotta il comando COPY di PostgreSQL, che garantisce velocità elevata ma richiede la presenza preventiva della tabella. Si rende quindi necessario automatizzare anche la creazione della struttura.
La soluzione prevede l’uso di Python con psycopg2, che consente esecuzione diretta di SQL senza overhead. Lo script scorre i file CSV, utilizza il nome del file come nome della tabella e legge l’intestazione per ricavare le colonne.
Viene generata dinamicamente una CREATE TABLE, con tutte le colonne definite come TEXT per evitare errori durante l’import. Eventuali tabelle esistenti vengono eliminate per garantire coerenza del processo.
I dati vengono quindi caricati tramite copy_expert, che esegue COPY mantenendo le prestazioni native di PostgreSQL.
Il risultato è una pipeline automatizzata che gestisce creazione e import senza intervento manuale. La scelta del tipo TEXT è intenzionale: consente un caricamento rapido e robusto, rimandando la tipizzazione a una fase successiva.

ENG
There is a need to import multiple CSV files into PostgreSQL efficiently and without repetitive manual operations. The initial approach using pandas and to_sql allows full automation but is inefficient due to the use of multiple INSERT operations instead of a bulk load, resulting in a total processing time of about 15 minutes for 700MB of data.
To improve performance, the PostgreSQL COPY command is adopted, as it provides high speed but requires the target table to exist beforehand. Therefore, it becomes necessary to automate the table creation process as well.
The solution involves using Python with psycopg2, which allows direct execution of SQL without additional overhead. The script iterates over CSV files, uses the file name as the table name, and reads the header to extract column names.
A CREATE TABLE statement is dynamically generated, with all columns defined as TEXT to avoid errors during import. Any existing tables are dropped to ensure process consistency.
The data is then loaded using copy_expert, which executes the COPY command while preserving PostgreSQL’s native performance.
The result is a fully automated pipeline that handles both table creation and data import without manual intervention. The choice of the TEXT data type is intentional: it enables fast and robust loading, deferring proper data typing to a later stage
